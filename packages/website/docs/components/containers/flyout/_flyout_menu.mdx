`EuiFlyoutMenu` is the top menu bar of a flyout. It is a private component, and is controlled by the `flyoutMenuProps` and `flyoutMenuDisplayMode` props of `EuiFlyout`.

```tsx interactive
import React, { useState } from 'react';
import { EuiFlyout, EuiFlyoutBody, EuiFlyoutFooter, EuiButton } from '@elastic/eui';

export default () => {
  const [isFlyoutVisible, setIsFlyoutVisible] = useState(false);

  let flyout;

  if (isFlyoutVisible) {
    flyout = (
      <EuiFlyout
        onClose={() => setIsFlyoutVisible(false)}
        flyoutMenuProps={{
          title: 'My flyout with a menu',
          trailingActions: [
            {
              iconType: 'gear',
              ['aria-label']: 'Settings',
              toolTipContent: 'Settings',
              onClick: () => {
                window.alert('Settings clicked');
              },
            },
          ],
        }}
      >
        <EuiFlyoutBody>Flyout body</EuiFlyoutBody>
        <EuiFlyoutFooter>Flyout footer</EuiFlyoutFooter>
      </EuiFlyout>
    );
  }

  return (
    <>
      <EuiButton onClick={() => setIsFlyoutVisible(true)}>
        Show flyout with menu
      </EuiButton>
      {flyout}
    </>
  );
};
```

Actions rendered via `trailingActions` show a tooltip when `toolTipContent` is provided, and are placed before the close button. Use `leadingActions` to render actions at the start of the menu bar, after any built-in leading controls (pagination, or back/history); a divider is shown automatically between the built-in controls and `leadingActions` when both are present.

Each action accepts any `EuiButtonIcon` prop and arbitrary `data-*` attributes. See [EuiFlyoutMenuAction](#EuiFlyoutMenuAction). The menu bar sets `color`, `size`, `display`, `iconSize`, and `isSelected` itself so every action looks the same.

When an action is disabled, provide `toolTipContent` to explain why. Also set `hasAriaDisabled` so the button stays focusable and keyboard users can reach the tooltip.

:::info Deprecation
The `customActions` prop is deprecated in favor of `trailingActions`. It is still supported as a compatibility alias, but if both `trailingActions` and `customActions` are supplied, `trailingActions` takes precedence.
:::

In [managed session flyouts](#flyout-session-management), the Flyout Manager automatically adds a back button and a history popover control to the flyout menu for navigating to different flyout sessions within the managed context. The history popover is only added once there is more than one session to navigate back to; with a single previous session the back button alone is shown, since the popover would duplicate it.

#### Maximize

Set `showMaximizeButton` in `flyoutMenuProps` to add a maximize/restore toggle after the `trailingActions`. A maximized flyout fills the full width of its `container`, or the viewport when there is no container, so a container-scoped flyout never covers navigation or sidebars outside the container. The flyout's `size`, `type`, and `resizable` props are not changed: the resize handle is hidden while maximized, and restoring returns the flyout to the width it had before, including a width set by dragging.

In a [managed session](#flyout-session-management) with a child flyout open, only the child shows the toggle. Maximizing the child keeps the main flyout's width and fills the rest of the container. Opening a child restores a maximized main flyout.

A maximized `type="push"` flyout stops pushing the page content, but otherwise keeps push behavior, such as not closing on Escape.

Use `onMaximizeChange` to react to the change, for example to persist the user's preference. It is called with the new state after every toggle, and with `false` when opening a child restores a maximized main flyout.

```tsx interactive
import React, { useState } from 'react';
import { EuiFlyout, EuiFlyoutBody, EuiButton, EuiText } from '@elastic/eui';

export default () => {
  const [isFlyoutVisible, setIsFlyoutVisible] = useState(false);
  const [isMaximized, setIsMaximized] = useState(false);

  return (
    <>
      <EuiButton onClick={() => setIsFlyoutVisible(true)}>
        Show maximizable flyout
      </EuiButton>
      {isFlyoutVisible && (
        <EuiFlyout
          size="s"
          aria-label="Maximizable flyout"
          onClose={() => setIsFlyoutVisible(false)}
          flyoutMenuProps={{
            showMaximizeButton: true,
            onMaximizeChange: setIsMaximized,
          }}
        >
          <EuiFlyoutBody>
            <EuiText>
              <p>{isMaximized ? 'Maximized' : 'Not maximized'}</p>
            </EuiText>
          </EuiFlyoutBody>
        </EuiFlyout>
      )}
    </>
  );
};
```

#### Menu display mode

By default, the flyout menu is rendered when `flyoutMenuProps` is provided and menu has meaningful content. You can control this behavior with the `flyoutMenuDisplayMode` prop on `EuiFlyout`:

- **`'auto'`** (default): Only render the menu when it has navigation content (back button, history, custom actions, or `showMaximizeButton`) or a visible title. Otherwise, use a standalone close button.
- **`'always'`**: Always render the menu, even if it only contains a close button.
